# 正式项目：资本投资文本预测

从原始 SEC 文本与 Compustat 财务数据构造可复现、逐步有记录的数据处理流程，预测企业资本投资强度变化。本目录为正式代码、配置、输出与文档；早期探索留在 `../analysis/`。

> **当前状态（2026-10-23）**：阶段 01 数据清洗已完成；独立预处理已生成 26,343 份文本—财务报告期候选（主 Y 可算 23,330 份）；第一版修正已实际构造财务 Y。但**真实申报日 / 报告期 / 表格类型仍未补齐，窗口内 47,604 份文本的真实匹配为 0，未拟合任何特征或训练模型**。下列结论均不宣称已完成训练数据集。

## 1. 目录结构与运行

```text
config.json                     年份、字段、筛选及清洗参数
requirements.txt                固定依赖版本
src/cleaning.py                 标识、文本及 TF-IDF 预览清洗函数
src/preprocess.py               全量清洗入口，自动写逐步 Markdown 记录
src/validate_run.py             独立校验全部输出并生成结果 Markdown
tests/                          保留否定、金额、日期等关键规则的验证
data/external/                  待导入的申报元数据（含空模板）
runs/<时间戳>/                   每轮独立的数据、报告、复核清单及操作记录（本地，不入库）
independent_preprocessing/      独立原始数据预处理（不读第一版产物）
p2_revision1/                   原包 p2_code 的独立修正工作副本
vendor/p2_code_original/        原包基线（只读，作为修改参照）
reports/                        财务缺失/分布/筛选表、文本分布、边界证据与审查证据
```

### 运行（本机临时 Python 环境）

```bash
# 阶段 01 清洗与独立校验
python -m unittest discover -s formal_project/tests -v
python formal_project/src/preprocess.py
python formal_project/src/validate_run.py

# 独立预处理（从原始数据重算，不读第一版）
python formal_project/independent_preprocessing/run.py
python -m unittest discover -s formal_project/independent_preprocessing -p 'test_*.py' -v
python formal_project/independent_preprocessing/validate.py

# 第一版修正工作副本（须先放真实申报元数据）
python -m pip install -r formal_project/p2_revision1/requirements-preprocess.txt
python formal_project/p2_revision1/src/run_all.py --preprocess-only
```

### 输出怎么用

- `annual_normalized.parquet` / `annual_scope.parquet`：统一范围、币种及行业后的财务表，尚未构造 Y 或日期匹配。
- `text_index_clean.parquet` / `text_clean/*.parquet`：2016—2023 文本索引与清洗全文，保留所有有效申报及待补元数据状态。
- `text_manifest.parquet`：逐文本哈希、长度、清洗动作、质量及复核标记。
- `reports/`：财务缺失/分布/筛选表、文本分布、边界截断证据、转换预览及待补申报清单。
- `quarantine/`：被筛财务记录、异常索引和需人工复核的文本；不是物理删除源数据。

## 2. 阶段 01 数据清洗

### 2.1 输入与范围

输入为原始年度 Stata 表与原始文本索引/文件，不依赖探索阶段缓存；季度数据暂不进入主任务。年度财务不截取年份，以保留前后年度；文本窗口为申报年 **2016—2023**。

### 2.2 清洗规则

| 步骤 | 操作 | 目的 |
|---|---|---|
| 1 | 记录源数据、代码 SHA256 与依赖版本 | 复现与追溯 |
| 2 | GVKEY 补足 6 位、CIK 去前导零、日期转 datetime | 统一键值 |
| 3 | 非有限数转缺失并计数；负/零值保留标记 | 负利润有效，异常 CAPX 另处理 |
| 4 | 依次筛 STD/INDL/C、USD、有效键、非空核心财务、非金融行业 | 每步记录数量 |
| 5 | 行业优先历史 sich，回退公司 sic 时标注来源 | 避免默认当前行业适用于历史 |
| 6 | 公司—财年重复整组隔离 | 不任意取第一条 |
| 7 | 输出缺失率、分位数、零负值与年度覆盖 | 尚不缩尾/填补/标准化 |
| 8 | 选定文本窗口、统一标识与申报编号，核对索引重复 | 日期未齐时不擅自去重 |
| 9 | 标记公司财务覆盖及 CIK/GVKEY 对应 | 公司交集 ≠ 财年匹配数 |
| 10–13 | 逐文本读取、UTF-8 检查、去目录/页码/重复布局块、识别 7A/8 章节、2500 字符后截断、保存全文与质量表 | 保留原文证据供预训练模型 |

**本轮不执行的拟合**：缺失 X 的中位填补、缩尾、标准化、TF-IDF 词表/IDF、PCA/SVD，均等待精确日期匹配与时间切分。Y 不填补，文本缺年不插值。

## 3. 真实数据重新核查与报告期候选（独立预处理）

### 3.1 重新核查原始数据

独立回到两个原始目录，发现此前遗漏的关键字段 **`apdedate`（Actual Period End date）**：年度表 208,735 行中 144,579 行非缺失，其中 6,855 行与 `datadate` 不同——因此"数据没有真实报告期"的说法不成立，缺的是逐申报对应表。两篇原文有明确年度期末证据，但 SEC 说明开头（"fiscal years 2010-2026"）与 `year` 字段定义存在措辞不一致，须采用明确字段定义并结合正文验证。SEC 索引（109,675 行）无独立申报日/报告期字段；`fdate`/`pdate` 不能仅凭标签替代；CIK 空字符串须剔除（剔除后 149,321 条有效）。结论：先保留 `apdedate` 等原始日期字段，基于正文会计期间与公司标识建立可审计候选。

### 3.2 独立预处理方法与结果

入口 `independent_preprocessing/run.py`，从原始 Compustat、SEC 索引与全文重新处理，**不读取第一版输出**，仅复用经检查的确定性文本清洗。最终运行 `independent_corrected_20261023T065859_817792`。

方法与差异要点：
1. 期末优先 `apdedate`，缺失回退 `datadate`；按 GVKEY+fyear 查准确前后年，实际期末间隔 330—400 天检查可比性。
2. 范围筛选 STD/INDL/C、USD、经营行业且非金融，歧义财年整组隔离；缺失指标保留，不以辅助 Y 或某 X 缺失删主任务候选。
3. 主 Y：`CAPX(t+1)/AT(t) − CAPX(t)/AT(t−1)`；辅助 Y：平均资产口径 ROA 变化；缺失 Y 及方向标签保持缺失；财务 F 保留原始尺度，未拟合。
4. 文本重新清洗并保存哈希；仅接受年度短语引出的日期列表，排除附近预测措辞（anticipate/expected/estimate/outlook）；日期不足不按申报年猜测；索引 GVKEY 冲突时不擅自覆盖。
5. 原始 10-K 与修订版身份未确认，重复公司年度仅标记；未知申报日/标签公开日仍缺失。
6. 候选 split 仅写入 2016—2019/2020/2021/2022—2023，尚未做真实公开日净化。

**提取修正**：第一轮宽日期窗口把年度后交易日混入期间列表，修正为仅接受日期/比较年份/连接词构成的列表；抽查发现 "year ended" 被用于 2023 Outlook 预测语境，补充预测语境识别并新增回归案例。

**复核与范围修正**：期间证据审计（`period_review_...`）发现 904 个重复公司年度组、1,891 行，整组隔离；证据分层 `repeated_results_evidence` 13,483 / `third_party_wording` 10,422 / `single_location` 1,843 / `no_results_context` 595。范围修正（`scope_period_refined_...`）修正历史行业回退逻辑（历史 sich 有值不被当前行业覆盖），重建前后年与 Y；136 份候选不再符合财务范围，56 份仅有旧报告引用证据。最终主任务期间复核池 21,743 份、辅助 21,777 份——**仍不是可训练样本**。6 项规则测试、9 项流程检查、8 项独立校验（含两类 Y 各 500 条原始回算）均通过。

## 5. 原包（p2_code）对照审查

依据最终方案及"保留现有深度学习和 RL，在这份代码上继续改"的要求，对 `vendor/p2_code_original/` 静态审查（19 个文件均可解析）。结论：可作修改基线，但目前主要是"规则因子 + 小型 Transformer"版本，部分时间与训练逻辑需先修正。

**已有 / 缺失对照**：财务合并与异常处理、TF-IDF（含 SVD 对比）、Ridge/Elastic/RF/XGBoost（含 SVM）、多任务 Transformer、RL 策略——均已有；FinBERT/MPNet 原文向量、Qwen 事件与摘要、Full/PCA 方法矩阵、真实预算对照与分项消融——均未实现（当前 `text_shootout.py` 明确用规则 CPS、从零 Transformer 代替，代理不能算完成真实模型比较）。

**优先修的关键问题**：
- **A. 滞后方向反了**：`features_text.py:67` / `capex_plan.py:268` 令来源 `py=fyear−1` 后以当前 `fyear=py` 合并，实际取到下一年特征；须严格按相邻财年构造并加断言。
- **B. RL 策略均值梯度被切断**：`rl_portfolio.py:139/:146` 用 `float(means[i].detach())` 建分布，均值网络无法学习；须保留 tensor 形式策略分布。
- **C. 财年/样本/Y 未对齐方案**：按申报年减 1 猜财年、主 Y 口径（代码 `(CAPX(t+1)−CAPX(t))/AT(t)` 与方案 `CAPX(t+1)/AT(t)−CAPX(t)/AT(t−1)` 不同）、ROA 分母、Y 固定范围裁剪、强制要求股价/收益筛选、窗口 2010—2022 缺独立验证窗、未过滤金融行业/USD。
- **D. 部分标准化用了测试分布**：`features_text.py:55` / `capex_plan.py:261` 的 SSI/CPS 综合分用全样本均值/标准差，应在每个训练窗口拟合。
- **E. Transformer 的 OOF 不能保证表示层独立**：先用训练期标签训练编码器再随机 OOF；验证随机抽 10%、最佳 checkpoint 未重载、只取前 256 词。
- **F. RL 回测缺可信决策时点**：收益起点早于年报公开、整年平均信号分位组、状态预按固定组合算好、训练/测试期混算、按简单相加收益而非复利净值。

**修改顺序**：① 修数据底座（接正式清洗与元数据，修正滞后方向、Y 公式、范围与时间切分）；② 补文本路线（FinBERT/MPNet/Qwen）；③ 修并保留 Transformer（时间验证、折外表示、最佳权重、全文分块）；④ 修并保留 RL（梯度、时点、收益、状态、测试期指标）；⑤ 统一实验与报告后重跑再更新结论。
