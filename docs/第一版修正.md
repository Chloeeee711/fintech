## 2. 每一步改了什么

### ① 接上本地已经清洗的数据

`config.py`改为相对项目路径，移除他人电脑路径；窗口改为2016—2023申报年。`data_prep.py`读取此前全量清洗run `20261022T215534_307871`的财务与文本清单，并记录输入、配置与源码SHA256。

沿用已完成的规则：年度数据；STD/INDL/C、USD；有效经营行业且排除金融业；优先历史行业代码；财年歧义隔离；原始文件不改。该轮清洗保留87,257条财务记录、47,604份窗口内文本。本轮没有重新清洗全部原文，而是复用有哈希和复核标记的完整清洗文本。

### ② 财年按真实日期匹配

删除“文件年份减1，匹配不上再用当年”的猜法。必须提供：

```text
accession_key, filing_date, report_period_end, form_type, metadata_source
```

放入`formal_project/data/external/filing_metadata.csv`；同目录已有空模板。申报编号必须有效且唯一，日期和来源必填；不从文件名推测日期。

- 用`GVKEY＋真实报告期末日`匹配财务记录，并核对CIK。
- 原索引缺GVKEY时，才用`CIK＋真实报告期末日`回退；仅接受唯一匹配。已提供但冲突的GVKEY不被静默覆盖。
- 申报日不得早于报告期，须与索引申报年份一致；本轮只纳入原始`10-K`，修订版不当作独立年度样本。
- 同公司同财年多份原始10-K，按实际申报日取最早一份；其余在审计表标记。
- 全年份索引都参与日期匹配，以便使用2024年等后续申报确定2023样本的标签公开日；最终预测样本仍限2016—2023申报年。

当前文件没有这些元数据，所以所有窗口内文本保持“待匹配”，**不会用猜测得到的财年继续训练**。

### ③ 按最终方案重算Y

`preprocessing_v1.py::financial_panel`按`GVKEY＋准确财年`连接`t−1、t、t+1`，不把相邻行直接当相邻年。

| 字段 | 定义 |
|---|---|
| `capex_int` | `CAPX(t)/AT(t−1)`，历史投资强度，属于X |
| `capex_int_fwd` | `CAPX(t+1)/AT(t)` |
| **`d_capex_at`：主Y** | `CAPX(t+1)/AT(t) − CAPX(t)/AT(t−1)` |
| `roa` | `NI(t)/[(AT(t−1)+AT(t))/2]` |
| `roa_fwd` | `NI(t+1)/[(AT(t)+AT(t+1))/2]` |
| **`droa`：辅助Y** | `roa_fwd − roa` |
| `*_up` | 对应Y＞0为1，否则0；Y缺失则分类标签也缺失 |

必要资产分母须为正，相关CAPX须非负；所需财年必须存在。另加330—400天相邻年报期检查，避免改财年或短会计期与完整年度直接比较。异常和缺失Y保留缺失，不用均值补、不截断为人为范围。

原字段`d_capex_at`名称保留以便后续接代码，但**含义已按最终方案修正**，旧结果不可与新口径混用。

### ④ 财务X补齐，按任务筛样本

财务F为：历史投资强度、ROA、收入增长、现金/资产、负债/资产、`ln(总资产)`、两位SIC行业。收入增长要求上一年收入为正，负现金/负负债比率记为待处理缺失。

主任务只按主Y有效性筛选，辅助任务另存；不因缺股价、收益率或辅助Y而删除主任务记录。原始F与Y保存在财务候选表，未经填补或缩尾。

`FinancialTransform`在划定训练集后：

1. 仅用训练集估计数值X的1%/99%分位数并缩尾。
2. 仅用训练集缩尾后的中位数填补X，同时输出每列缺失标志。
3. 仅用训练集均值、标准差标准化数值X。
4. 行业词表只来自训练集；验证/测试的新行业归`UNKNOWN`。

训练中整列缺失的X用0及缺失标志兜底，列名写入状态文件供复核。**这些处理只针对X，不对Y做任何填补。**

### ⑤ 文本保留完整语义

`features_text.py`改为调用`feature_prep_v1.py`，按申报编号读取此前清洗的完整文本分片并逐篇核对清洗哈希。删除原先只读取前12,000字符的做法，读取失败或空文本不再替换成空字符串。

- TF-IDF单独分词，保留否定词、数字和年份，支持一元/二元词组；词表、IDF仅在训练集拟合。
- 验证集和测试集只转换，分别保存矩阵及申报编号顺序表，防止矩阵和样本错位。
- FinBERT、MPNet、Qwen后续使用保留金额、时间、否定、标点的自然文本；本轮没有运行这些模型，也没有将分词后文本送给它们。
- 过短、重复或其他需复核文本先隔离，未复核不进入正式样本；不会将“缺文本”编码成“不投资”。既有复核标记不自动清除，人工放行流程仍待补。

原始词典/SSI规则保留作基准；它们不能冒充FinBERT或Qwen。

### ⑥ 修正因子泄漏与人工抽查

原SSI/CPS使用全样本均值、标准差，现改为只在训练集拟合；保存参数和拟合样本编号。

原滞后键方向反了，会把下一年因子接到当年。现统一`exact_lags`：将历史记录财年加1后接到当年，只接受同公司准确`t−1`且已在当前申报日前公开的记录。缺年保持缺失；只有一份文本的公司仍可做水平因子预测，不强求滞后因子完整。

`capex_plan.py`另修正：

- 规则未检出投资主题时，主题标志为0，但金额、阶段等条件分数记缺失，不能解释为实际投资为0。
- 抽查从全部文档中分层随机抽句，包含规则阳性和阴性；最多各50句，小样本也能运行。
- 保存申报编号、公司、财年、句子位置及完整句子；金额“是否出现”和“启发式数值”分列。
- 已有人工标注表不覆盖；记录抽样总体规模。这个分层诊断样本不能直接算未经加权的总体召回率。

金额主体、币种、时态、混合预算等语义规则尚待Qwen与人工核验；原有规则提取器本身没有被当作可靠真值。

### ⑦ 时间划分与标签公开日

候选划分沿用最终方案：训练2016—2019，验证2020，2021缓冲，测试2022—2023。再按下一财年原始10-K实际申报日过滤标签：

- 训练标签必须在2020-01-01前已公开，否则该行不进入训练。
- 验证标签必须在2022-01-01前已公开。
- 可评分样本要求标签公开日在当前申报日之后；未知公开日不进入正式评分样本。

因此训练窗口可能进一步收缩，不能为了保住2019样本而使用2020年才公开的标签。本轮特征比较固定主任务样本，辅助Y缺失不删主任务行；辅助任务候选另外保存。

### ⑧ 保留RL和深度学习

工作副本保留`transformer_encoder.py`、`rl_portfolio.py`，独立校验确认二者与原包逐字节相同。没有删除，也没有运行训练。

`run_all.py --preprocess-only`允许运行本轮预处理；默认全流程训练暂时明确报错，避免旧训练逻辑读取新口径数据后生成误导结果。原包深度学习的随机验证/监督表示、RL策略均值断梯度、收益窗口和样本外评价等问题，留到下一轮专项修正。

**本轮不再构造原先未复权、起点早于申报日的收益率代理。**后续RL独立接预测时点之后的可靠收益标签，不作为主Y筛选门槛。预处理依赖列表也不表示完整深度学习环境已安装。

## 4. Qwen2.5-14B-Instruct怎么获取

**免费获取模型权重，不等于有永久免费云API。**指定模型的官方下载是[Qwen官方模型页](https://huggingface.co/Qwen/Qwen2.5-14B-Instruct)。本轮没有找到可确认持续免费、且明确提供该14B型号的云端接口。

### 路线A：本地或学校服务器运行，不需要申请云API Key

在有合适硬件的电脑上，可按[Qwen官方Ollama说明](https://qwen.readthedocs.io/en/v2.5/run_locally/ollama.html)安装Ollama，使用其[14B Instruct模型](https://ollama.com/library/qwen2.5%3A14b-instruct)：

```bash
ollama pull qwen2.5:14b-instruct
ollama serve
```

Ollama应用已经运行时通常不用重复启动服务。随后可通过本机接口`http://localhost:11434/api/chat`调用。模型下载和运行不收云API调用费，但需要自己的硬件、内存与运行时间。本轮没有下载模型或实测你电脑的速度。

学校有GPU服务器时，也可按[Qwen官方vLLM部署说明](https://qwen.readthedocs.io/en/v2.5/deployment/vllm.html)部署原始`Qwen/Qwen2.5-14B-Instruct`并提供兼容接口。使用Ollama量化版本时，报告需写明具体模型标签、量化及运行设置，不能与原精度版本混写。

### 路线B：云API，先核实型号与额度

可查看[魔搭API服务](https://modelscope.cn/docs/model-service/API-Inference/intro)及[公开可调用模型列表](https://api-inference.modelscope.cn/v1/models)。**2026-10-23查询的公开列表没有`Qwen/Qwen2.5-14B-Instruct`**，因此不能承诺注册后就能免费调这个型号，也不能擅自换成Qwen3完成实验。账号是否另有可用服务，以登录后模型服务页为准。

[硅基流动官方快速开始](https://api-docs.siliconflow.cn/docs/userguide/quickstart)说明了注册、创建API Key及`https://api.siliconflow.cn/v1`的用法；但需在[当前价格和模型页](https://www.siliconflow.cn/pricing)确认指定14B是否可用、是否收费或仅有赠送额度。本轮未确认该型号的免费额度，没有注册、充值或调用。

模型保持指定14B时，优先落实本地/学校服务器；如教师给过具体免费平台，应先以那个平台核实。Key保存在自己电脑的环境变量中，不写进代码、Markdown或聊天。`p2_revision1/qwen_api.example.json`只是禁用状态配置模板，尚无实际调用。
