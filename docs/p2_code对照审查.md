# p2_code 对照最终方案审查

日期：2026-10-23。依据当前《资本投资选题最终方案》及用户最新要求：**保留现有深度学习和RL，在这份代码上继续改。**

**结论：可以作为修改基线，但目前主要是“规则因子＋小型Transformer”的版本，尚未实现最终方案中的完整预训练模型比较；部分时间和训练逻辑需要先修正，现有结果不能直接作为最终结论。**

原始解压代码在`formal_project/vendor/p2_code_original/`；逐文件与ZIP核对完全一致。本轮没有修改原代码、执行训练、反序列化joblib或重新生成收益。下面既包含缺失功能，也包含已定位的代码问题。

## 2. 优先修的明确问题

### A. “上一年”特征实际取了下一年——最高优先级

位置：`src/features_text.py:67`、`src/capex_plan.py:268`。

代码先令来源行`py=fyear−1`，再以当前行`fyear=py`合并。于是当前2018年取得来源2019年的特征，而不是2017年。`lag_ssi、lag_tone、lag_cps_*`和相关动态结果被影响；`capex_empirical.py:205`还要求这些错误lag非缺失，令基础样本也依赖未来文本是否存在。

修法：来源年份加1后对齐，或严格按相邻财年构造滞后；增加“来源财年必须等于当前财年−1”的断言。不能只改字段名。

### B. RL策略均值网络梯度被切断——最高优先级

位置：`src/rl_portfolio.py:139`、`:146`。

`m=float(means[i].detach())`后，用这个常数创建`Normal(m,std)`来计算损失。策略均值与网络权重间的梯度链已经消失，损失只能通过`std`等仍在计算图里的量传播；决定确定性仓位的`policy.net`无法按该损失学习。

修法：保留tensor形式的均值计算策略分布和log_prob；使用与动作边界一致的分布/变换，并验证均值网络参数实际更新。增加“参数更新、策略优于固定仓位”的独立检查。

ZIP内RL仓位约45%—46%，与固定50%仓位的Sharpe非常接近，这是既有JSON现象，不是本轮重跑结果。当前不能把回撤减半归因为RL学到了有效策略。

### C. 财年、样本和Y没有对齐最终定义

位置：`src/data_prep.py:71`、`:98`、`:113`、`:140`；`src/config.py:25`。

- 按申报年减1、未匹配再尝试当年；没有实际申报日和报告期。
- 代码主任务是ΔROA，最终方案主任务是投资强度变化。
- 代码投资Y是`(CAPX(t+1)−CAPX(t))/AT(t)`；方案是`CAPX(t+1)/AT(t)−CAPX(t)/AT(t−1)`，不是同一个指标。
- 代码ROA为`NI/期末AT`，方案为`NI/平均AT`；还对Y做固定范围裁剪。
- 主样本强制要求股价和`ret_1y`存在，并按未来收益筛选，导致投资/盈利研究被不必要的交易条件决定。
- 窗口为2010—2022、2020起测试；缺独立年度验证窗；未过滤USD和金融行业。

修法：统一目标公式和期间；主样本不依赖收益，RL另建有收益数据的子样本；按实际公开日切分。旧口径可保留为稳健性，但不可沿用同名冒充新定义。

### D. 部分标准化用了测试分布

位置：`src/features_text.py:55`、`src/capex_plan.py:261`。

SSI与CPS综合分用全样本均值、标准差。无监督也不代表适合样本外实验。应在每个训练窗口拟合，后续年份只transform。TF-IDF本身已只在train拟合，这部分可以保留。

### E. Transformer的OOF不能保证表示层独立

位置：`src/transformer_encoder.py:149`、`:189`、`:195`。

- 先用训练期标签训练编码器，生成整段训练表示，再只对Ridge探针随机OOF；部分留出行的标签已进入上游表示学习，不能称为完整无泄漏OOF。
- 验证是随机抽10%，探针KFold也随机打乱，不满足按时间模拟预测。
- 保存最佳checkpoint后没有重新加载，随后用最后一轮模型生成向量。
- 辅助风险标签来自词典，本轮高AUC只说明复现弱标签的能力；测试标签还用了测试期自身中位数，与训练阈值不一致。
- 只取前256个词，无法代表完整长文计划。

修法：保留网络，按时间窗口训练和验证；需要堆叠的neural_score时，上游编码器与探针一起按时间生成折外特征，或另设独立表示训练期；加载最佳模型；固定训练阈值；分块聚合长文。单纯“训练期监督学习后评价真正后期测试集”并不自动泄漏，问题是当前训练折外构造和时间协议不足。

### F. RL回测还缺可信的决策时点

位置：`src/data_prep.py:87`、`src/rl_portfolio.py:57`、`:76`、`:163`。

- 用财年末股价比作为收益，收益起点通常早于年报公开；它也不是已核验的复权含分红总收益。
- 用整年申报的平均信号和分位组决定该年仓位，没有统一信息可用时点。
- 状态中的历史累计值/回撤预先按固定底层组合算好，并非代理动作后的资产状态。
- 训练用早期年份，但最终Sharpe/回撤是2010—2022全区间，混合了训练期和测试期。
- 累计值与回撤按简单相加收益计算，而非复利净值；只计仓位变化成本，未计底层选股换仓、做空等成本。

修法：保留RL作为策略扩展，单独定义决策日、当时可用信号、决策后的收益；动态更新代理资产状态，分别报告训练/验证/测试，与固定50%、100%及简单规则同口径比较。现有价格比仅作明确标注的演示代理，不能作可交易策略结论。十个年度训练点反复400轮不会增加独立市场样本。

## 4. 工程复现还缺什么

- 路径写死为另一台电脑的`/Users/celeste/...`，未接入本地`formal_project`清洗输出。
- `run_all.py:37`未包含`text_shootout.py`和`verification_metrics.py`，报告脚本却读取它们的JSON，可能混用历史产物。
- 没有固定依赖文件、数据/配置指纹和逐轮独立输出；缓存主要只检查token长度，数据变化可能复用旧行。
- 核验CSV重跑会被覆盖为空白模板，应保护已有人工标注。
- ZIP含结果JSON/PDF，但不含生成它们所需的主要Parquet、向量、checkpoint，原始数据路径也不可用。它们应视为未复现的历史结果，而非本地已验证结果。

## 5. 保留RL和深度学习后的修改顺序

1. **修数据底座：**接正式清洗与元数据，修正滞后方向、Y公式、范围与时间切分；主任务和RL分开建样本。
2. **补文本路线：**真实FinBERT、MPNet、Qwen事件、摘要向量；CPS与SSI继续作为规则基准。
3. **修并保留Transformer：**时间验证、表示层折外、最佳权重、全文分块；作为额外DL信息块独立比较，不冒充Qwen。
4. **修并保留RL：**梯度、时点、收益、状态与测试期指标；先标注代理演示，数据满足后再作真实交易评价。
5. **统一实验与报告：**M0—M7、Full/PCA、消融、预算基准、正确统计与完整运行入口；全部重跑后再更新结论。
